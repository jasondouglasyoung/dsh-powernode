### `remote.directoryPicker` missing inject

Alpha.13 的独立桌面验收分别在工作区和输出目录按钮复现 `cannot get property "remote.directoryPicker" without inject`。锁定 DSH 0.2.0-rc.2 的 Cordis contract 将 picker 暴露为独立子服务；客户端旧注入上下文只包含根 `remote`。Alpha.14 在客户端 DSH manifest 中注入并 externalize workspace controller client，`apply()` 挂载 Typert Remote 后继续嵌套注入 `remote.directoryPicker`，等待该 Fiber 注册 UI，并把真实子注入 Context 传给 React 面板。服务缺失时仍显示插件目录浏览器并给出明确提示。

真实 Cordis `Context`/`Service` 回归先确认只注入根 `remote` 会抛出同款错误，再确认对子服务执行 inject 后 picker 可调用；路径测试覆盖中文、内部空格、首尾空白、成对引号、取消不变和输出目录边界。Alpha.14 tarball 中的 manifest/client 与源码一致。系统原生对话框尚未在 Alpha.14 桌面复验。

### 会话面板控制持续禁用

Alpha.13 独立报告显示 paused/needs_review 会话面板的暂停、停止、通过、驳回持续 disabled；全局视图可控制同一 Run。代码中 Run poll 每秒以新对象执行 `setRun(latest)`。旧 `openCommandDraft` 依赖 `run`/`workflow`，而会话初始化 effect 依赖该回调，导致回调身份变化后初始化 effect cleanup/restart、反复 `setBusy(true)` 并重新请求 `sessionState` 和 `sessionRuns`。原报告没有保存 RPC 次数，本报告不声称有实测数字。

Alpha.14 用 refs 读取最新编辑器/提案快照、固定打开草稿/提案回调身份，并将会话初始化、草稿订阅、主题监听、Run polling 拆开。开始和控制动作在 Promise pending 期间使用 ref 防重复派发，`finally` 清理 busy/in-flight。自动测试验证依赖稳定；Alpha.14 三个入口的按钮恢复、真实请求次数、切换会话和未保存编辑保留仍待桌面复验。

### `/powernode` 草稿和编辑建议状态

新增 session-keyed UI 状态，把 DSH `session/event` 命令开始/结束事件映射为生成中、完成、失败、取消；标题栏提供回到草稿或提案的入口。不会解析模型回复来修改聊天 composer，不自动保存、不应用提案、不启动 Run。普通聊天没有插件命令事件，不会调用工作流规划。自动测试覆盖状态终结、会话隔离和消息长度限制；真实 DSH 事件及切换会话行为未在 Alpha.14 窗口复验。


Alpha.13 真实 Agent 的 pwsh 报 `SetNamedSecurityInfoW failed (Win32 5): grantWrite($DemoWorkspace\验收 空格 20261004)`。插件 `agent-runner.ts` 只把经 Host 校验的 cwd 传给 DSH Agent 的 `meta.cwd`，没有 ACL 修改/`grantWrite` 代码；该错误不属于插件的执行目录配置。当前两个演示目录显示从父路径继承 `Authenticated Users: Modify`，本地 PowerShell 在本轮新建的英文和中文空格路径都完成 write/read 与相同 SHA-256（证据 [`pwsh-probe/result.json`]（本机 artifacts 文件不公开））。这说明普通本机文件写入权限可用；`Modify` 不等于修改 ACL 的 `WRITE_DAC` 权限，错误最可能发生在 DSH shell/sandbox 为 pwsh 工作目录授予 ACL 的初始化步骤。该结论属于源码与 ACL 的推断，不是已完成的普通 DSH Agent 对照。

四格对照现状如下。`pwsh-probe/result.json` 是普通本机 PowerShell 测试，不等于 DSH Agent：

|---|---|---|
| 普通 DSH 会话 | NOT_RUN：需用 file read/write 和 pwsh 最小探测 | NOT_RUN：需用 file read/write 和 pwsh 最小探测 |
| 插件 Agent | NOT_RUN | 历史 Alpha.13 文件 read/write 成功；pwsh 在 `grantWrite(...)` 失败（Win32 5）。 |
| 本机 PowerShell | write/read PASS | write/read PASS |

Alpha.13 报告未给同一 DSH Agent 工具分别对两种目录执行的完整结果，本轮也无法操作 DSH UI。下一次复测使用专用英文目录和 `中文 空格` 目录，对普通会话和插件 Run 依次调用文件读写与 `pwsh Get-Location`、文件创建/读回，并保存调用方/工具结果。需关注影响面是 DSH Agent 配置 working directory 时要执行 ACL grant 的 Windows pwsh 路径；插件的 DSH file tools 已有成功证据。当前推断适用于 Windows 继承 `Modify`、但 Agent sandbox 还需授予 ACL 的目录，不构成对其他 Windows ACL 或其他系统的兼容声明。没有依据把工具权限失败归因于插件配置并修改权限，也没有放宽安全边界。
