# 演示工作流文字规格

本规格只用于后续工作流编辑器开发与验收，不是可导入的 JSON。

## 三个任务节点

1. 分析需求：读取 requirements.md、style-guide.md 和 prompt-example.md，归纳页面结构、文案、响应式规则和检查项。
2. 实现页面：依赖“分析需求”的结论，读取同一组输入，在 outputs/ 中生成 index.html 与 style.css。
3. 检查产物：依赖“实现页面”，读取 outputs/index.html 与 outputs/style.css，核对文件存在、配色、三张卡片与 360 px 单列布局，并写出检查结果。

## 关系

- 任务依赖边：分析需求 → 实现页面 → 检查产物。后续串行执行时，上游完成后才启动下游。
- 上下文关联边：三个任务都关联 requirements.md；实现页面和检查产物还关联 style-guide.md 与 prompt-example.md。检查产物额外读取实现页面生成的两个输出文件。
- 依赖决定先后顺序；上下文关联只表示某节点需要读取哪些文件或提示词，不隐含执行顺序。

## 编辑演示

- 人工插入任务：在实现页面与检查产物之间加入“人工验收”，说明其依赖实现页面，且检查产物依赖人工验收。
- 修改提示词：将 prompt-example.md 中一条实现要求改成卡片标题必须不超过 8 个汉字，并让检查任务据此核对。
- 故意失败：把检查任务的移动断点要求改成 320 px，但实现页面仍按 700 px 单列断点。检查应报告规格不一致并失败，不得伪造通过结果。
